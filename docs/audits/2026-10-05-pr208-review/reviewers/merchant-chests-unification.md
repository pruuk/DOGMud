# PR #208 review: merchant chests, unification lens

Blind reviewer `merchant_chests:unification`, run 2026-10-05 against PR head `3ce674451`. Findings were then checked by independent verifiers (three for critical and high, one otherwise). Severity is the verifiers' median. Back to the [synthesized report](../README.md).

## Reviewer summary

Merchant chests (f546918ec) reuse several shared mechanisms correctly, but in a number of places they build parallel ones. The two most serious problems are exploits that come from bypassing a shared mechanism. (1) WatchMerchantChest builds its own thief score and runs the observer contest without going through theftAttempt, the steal path's only gate for the skullduggery cooldown and the rank-2 requirement. A thief can retry a chest take every round with no cooldown and train skullduggery each time. (2) The guard on `put` was added only to the player command. The mob put command, which AI companions use for their put errand, can still over-fill a picked chest so its goods spill onto the floor, where anyone picks them up unmarked and unwatched. Medium drift: a relock clock kept only for chests, written instead of fixing a real bug in gamelock.Lock.IsLocked, so doors and every other locked container still never relock. A `lookout_mobs` list that runs alongside the `guard` group, so the justice tick never enforces what a lookout reports. A sleeping-merchant Perception multiplier that leaks into every sneak, search and detection check and contradicts the existing sleep policy in messaging. Balance formulas kept in world data YAML that do not actually drive the live values. A second stolen-state model on the item that copies the bauble Record's heat logic. A fence sale path copied from the bauble one, while `offer` quotes a price the sale may then refuse. Chest gold and goods are created from nothing, outside the living-economy ledger.

Correct reuse (credit): the observer contest goes through the existing stealObserverPass and combat.RunContest. The catch goes through thiefCaught and theftCrime, with theftReported split cleanly out of thiefCaught. Recognition reuses recognitionRoll, canRecognize and messaging.CanSeeShapes/CanSeeClearly. Heat reuses baubles.HeatDuration/HeatArea and Balance.BaubleStolenHeatHours/BaubleHeatAreas. baubles.ItemIsHotIn was extended, so storage and the auction house refuse hot goods with no new code. Fence pricing reuses FencePrice/BaubleFenceBuyPct and IsFence. Lock rotation reuses gamelock RotationSeed/SetLocked. The scheduled restock runs from a NewRound hook (events.RegisterListener), and the restock clock is kept in room long-term data. items.SameStack was extended so stolen and clean goods do not merge. Crafting and salvage refuse hot goods through the existing componentTagOf and salvageItem checkpoints.

### F012 [medium] Sleeping-merchant Perception multiplier is a bespoke attention rule that leaks into every sneak, search and detection check

`internal/actions/merchant_chest.go:30` · status **confirmed** · reported as medium

sleepingMerchantPerceptionMult scales Perception by the catalog's sleeping_perception_mult, but only for a mob with a shop. It is applied inside the shared stealVictimScore and CalcDetectionScore. CalcDetectionScore feeds move.go sneak-in detection, newcomerSpots, sneak.go, search.go, track.go, shadow.go and plant/steal search, so a merchant-chest data file now retunes how every sleeping shopkeeper detects sneakers world-wide. The rule also contradicts the codebase's existing sleep policy. messaging treats sleep as attention (awake() composed into CanSeeClearly/CanSeeShapes: a sleeper perceives nothing). Theft code already follows that: canRecognize and household isResident exclude sleepers outright. Under the new rule a sleeping merchant still watches at 50%, while a sleeping guard or player in the same room still watches at 100% (stealObserverPass has no sleep check). The knob itself lives in merchant_chests.yaml rather than config.balance.go. It also re-implements existing helpers: `len(c.Shop) == 0` instead of mobs.(*Mob).HasShop, and HasConditionFlag(Sleeping) instead of TargetAsleep.

**Failure scenario.** A player sneaks into an inn at night where the innkeeper and a guard both sleep. The innkeeper's detection is halved, the guard's is untouched, and neither is excluded as the household-bauble and recognition paths would exclude them. Retuning sleeping_perception_mult in the merchant-chest catalog changes sneak and search outcomes in every shop room, which no one editing that file would expect. A world without the catalog file gets 1.0 everywhere.

**Existing mechanism.** messaging sleep policy (predicates.go awake / CanSeeShapes), actions.TargetAsleep (sleeping_target.go), mobs.(*Mob).HasShop, balance knobs in internal/configs/config.balance.go

**Suggested fix.** Decide sleep-in-contest once, for all observers, in stealObserverPass / the detection callers, using the messaging attention policy (or a Balance knob such as SleepingObserverPerceptionMult in config.balance.go). Do not special-case merchants inside the two shared score functions.

### F013 [medium] Chest theft runs its own contest and skips the steal path's cooldown and rank gate: free retries and skill farming

`internal/actions/merchant_chest.go:68` · status **confirmed** · reported as high

thiefScore copies the attacker score that newTheftAttempt (steal.go:191) computes: Dex + skullduggery x SkillWeight + StealHiddenBonus, x SightMult. But WatchMerchantChest feeds that score straight into stealObserverPass and never goes through theftAttempt.score(). The baseline comment calls that call the single place that arms the skullduggery cooldown, so that "no contest can run without spending it". It also skips the rank < 2 gate that stealFromContainer applies (steal.go:546). Because `get` from a merchant chest is now a theft verb outside Steal, every chest take and every new picklock prompt is a theft contest with no cooldown and no rank floor. Take attempts also call AwardResolved for skullduggery on every roll, win or lose (line 100).

**Failure scenario.** A rank-0 character picks a merchant chest while the merchant is away on its schedule (merchantCatchesThief only runs when OwnerIn finds the owner; line 124). A player bystander or a guard is in the room. `get gold chest` is caught: the thief is revealed but the chest stays open, and the only penalty is the caught-this-round key (usercommands/merchant_chest.go), which lasts one round. Next round the thief re-hides and tries again, with no skullduggery cooldown, until the contest is won. Each attempt also trains skullduggery, which `steal` itself rate-limits with StealCooldown. Players with no Skullduggery rank at all can do container theft that `steal <container>` refuses them.

**Existing mechanism.** internal/actions/steal.go newTheftAttempt / theftAttempt.score() (the one cooldown-arming theft score) and the rank<2 gate in stealFromContainer

**Suggested fix.** Build the score with newTheftAttempt(char, room, cfg) and call t.score() right before stealObserverPass, so the cooldown is armed exactly once per attempt. Check TryCooldown/rank up front, as Steal does. Better still, route chest takes through stealFromContainer, as the household bauble does (get refuses and names `steal`).

### F014 [medium] Fence sale for stolen goods copies the bauble sale; offer quotes a price the sale may refuse

`internal/actions/sell_stolen.go:117` · status **confirmed** · reported as medium

sellStolenToFence is a near line-for-line copy of sellBaubleToMerchant. It includes the reserve check copied from baubleOfferFor, with the same `ratio <= 0 { ratio = 0.50 }` fallback, and inlines baubleMerchantGold. Divergence has already started on the quote side. offer.go quotes stolen goods with a raw actions.FencePrice(itemSpec.Value), while baubles quote through actions.BaubleOfferFrom, which applies the living-economy reserve and the broke refusal. **Existing mechanism.** actions/sell_bauble.go baubleOfferFor / BaubleOfferFrom / baubleMerchantGold / sellBaubleToMerchant; shops.ShopInventory Gold and stock as the merchant's ledger

**Suggested fix.** Generalise the bauble offer into a stolen-goods offer (price + reserve + refusal) used by both offer and sell, and share one gold-transfer/save helper. Consider drawing chest gold and goods from the ShopInventory so theft depletes the merchant.

### F016 [medium] Bespoke chest relock clock written around a confirmed gamelock.IsLocked bug instead of fixing it

`internal/merchantchests/restock.go:187` · status **confirmed** · reported as medium

The MarkOpened comment correctly finds that gamelock.Lock.IsLocked never relocks: it measures the relock period from the current round (`gametime.GetDate(rndNow)`) instead of from UnlockedRound. Instead of fixing the shared lock (a one-token change), the PR adds an in-memory relock clock (chestClock.openedAt) and a Tick relock pass that covers merchant chests only. The shared bug stays: every other picked or unlocked container and exit with a RelockInterval still never relocks. syncContainer also writes s.RelockInterval into c.Lock.RelockInterval (line 132), which the broken IsLocked reads but never acts on. The same knob is now read by two mechanisms, and one of them is dead. If gamelock is fixed later, IsLocked starts reporting the chest locked once the interval has passed, but without SetLocked's RotationSeed bump. The two relock paths then disagree about whether the keyring combination rotated.

**Failure scenario.** Any authored locked chest or door elsewhere in the world, once picked, stays open until reboot, regardless of its `relockinterval:`. Merchant chests alone relock, so locks behave inconsistently across the world. A later fix to gamelock silently doubles up with the chest clock.

**Existing mechanism.** internal/gamelock/gamelock.go Lock.IsLocked / RelockInterval / UnlockedRound

**Suggested fix.** Fix IsLocked to measure from l.UnlockedRound (gametime.GetDate(l.UnlockedRound).AddPeriod(...)). If rotation on relock matters, rotate RotationSeed when relock is observed, in gamelock, for all locks. Then delete openedAt/MarkOpened and the relock half of Tick.
